Fonte: OSRS Wiki, consultada em 26/09/2026. As abas e itens vêm da página *Collection log*,
cruzados com os dados de loja da wiki (bucket `storeline`) e conferidos página a página
nos casos que não são uma loja comum.

## Parte 1 — Conteúdos com itens de collection log comprados com pontos/moeda

Legenda do tipo de aquisição:
- **SHOP**: compra direta com a moeda do conteúdo
- **UPGRADE**: compra que consome outro item do log (ex.: Lumberjack → Forestry)
- **RANDOM**: gasta pontos numa rolagem (só dá para estimar pelo valor esperado)
- **MILESTONE**: liberado por contagem (vitórias, kills, tempo), não por gasto

### Pontos validados (26/09/2026)
- **Uncut onyx**: a compra com tokkul **não** marca o slot; só conta o drop de monstro (página *Uncut onyx*).
  O gem stall do Mor Ul Rek também não conta. → **Fora do plugin.**
- **Boat Paints**: nenhuma é comprada com moeda. São drops raros, marcos de rank no Barracuda Trials
  ou recompensas de missão. A única troca é o Merchant's paint, que se consegue entregando 5 paints
  diferentes ao Trader Stan (troca de itens, sem moeda). → **Fora do plugin.**
- **Vale Totems**: os pontos ficam na variável de jogador **`VarPlayerID.ENT_TOTEMS_RESEARCH_POINTS` (4764)**
  (API do RuneLite, `gameval`). Loja: 1.120 pontos para um de cada item; mais 1.250 para maximizar o
  Bow string spool (meta opcional, fora do log). Ironmen podem vender itens de volta à loja por pontos.
- **Itens compartilhados**: confirmado pela seção *Duplicate entries* da wiki: o item não é rastreado
  separadamente e conta uma vez só no total. Os pares relevantes são:
  - Angler (4): Fishing Trawler + Aerial Fishing
  - Prospector (4): Motherlode Mine + Volcanic Mine
  - Lumberjack (4): Temple Trekking + Forestry
  → O custo entra **uma vez**, na moeda mais barata/escolhida pelo jogador.
- **Herb sack** (correção): **não** é duplicado. Só aparece na página do Tithe Farm. O Slayer shop
  (750 pts) é só outra forma de conseguir o item. A wiki não diz se a compra no Slayer marca o slot → validar no jogo.

### Achado útil para o plugin
A API do RuneLite tem varbits `COLLECTION_<ABA>_<PÁGINA>_COMPLETED`
(ex.: `COLLECTION_OTHER_VALE_TOTEMS_COMPLETED` = 17795). Isso pode servir de conferência rápida de
"página completa" sem abrir o log.

## Parte 2 — Proposta de plugin

### Nome provisório
**Reward Shop Planner** (ou "Clog Points Planner")

### O problema
Para fechar a parte "de loja" do collection log, o jogador precisa saber, para cada conteúdo:
1. quais itens ainda faltam,
2. quanto isso custa na moeda daquele conteúdo (às vezes em várias moedas e com upgrades em cadeia),
3. quanto já tem e
4. quanto tempo falta.

Hoje isso é feito em planilha ou na mão. Os plugins que existem cobrem um minigame só (MTA Goals,
Mixology Extended) ou só mostram os pontos.

### Funcionalidades (MVP)
1. **Painel lateral** com um card por conteúdo:
   - progresso de slots (ex.: Castle Wars 12/39);
   - para cada moeda: `tenho / preciso` e quanto falta;
   - horas estimadas (falta ÷ taxa/h configurável). Com várias moedas vale a **pior** delas, que é o gargalo.
2. **Detalhe do conteúdo**: lista dos itens com ✔ (já tem) / ☐ (falta). O jogador pode desmarcar o
   que não quer e ver a ordem de upgrades (ex.: Lumberjack → Forestry).
3. **Ordenação**: por menos horas restantes, menos pontos ou maior % concluída.
4. **Metas extras** fora do log (ex.: 10.760 Sawmill vouchers = 161.400 bark), somadas ao total da moeda.
5. **Modo de conta** (Main/Ironman), detectado pelos varbits. Para Mains, mostra o valor de revenda no GE
   dos itens negociáveis.

### Fontes de dados em tempo real
| O quê | Como |
|---|---|
| Itens que já tem | Sincroniza quando o jogador abre a página no collection log (`ScriptPostFired` da interface do log) + a mensagem "New item added to your collection log". |
| Pontos em varbit/varp | `client.getVarbitValue()` / `getVarpValue()` (IDs a mapear com o Var Inspector; ex.: Pest Control, Tithe, Foundry, MTA, BA, Mixology, LMS, Zeal, Carpenter, Volcanic Mine). |
| Moedas que são itens | Contagem em banco + inventário + (se houver) bolsa, via `ItemContainerChanged` (bark, tickets, pearls, marks, nuggets, tokkul, stardust, termites, pieces of eight, vouchers, hallowed marks). |
| Custos | JSON embutido (`activities.json`, `rewards.json`, `currencies.json`) gerado a partir da wiki por um script offline. Sem chamadas de rede em tempo de execução, o que também facilita a aprovação no Plugin Hub. |

### Modelo de dados (JSON embutido)
```json
{
  "currencies": [
    { "id": "anima_bark", "name": "Anima-infused bark", "source": "ITEM", "itemId": 0 },
    { "id": "pc_points", "name": "Commendation points", "source": "VARBIT", "varbit": 0 }
  ],
  "activities": [
    { "id": "forestry", "name": "Forestry", "clogPage": "Forestry",
      "currencies": ["anima_bark"], "defaultRatePerHour": { "anima_bark": 1500 } }
  ],
  "rewards": [
    { "itemId": 0, "name": "Forestry hat", "activity": "forestry",
      "clogPages": ["Forestry"], "type": "UPGRADE",
      "cost": { "anima_bark": 1250 },
      "consumes": ["Lumberjack hat"],
      "materials": { "Oak logs": 60, "Mahogany logs": 60 },
      "requirements": [] }
  ]
}
```
(os IDs de item/varbit e a taxa/h são placeholders que serão preenchidos na geração dos dados)

### Regra de cálculo
```
para cada conteúdo:
  faltando = itens do log ainda não obtidos (e não desmarcados pelo jogador)
  custo    = soma de cost[moeda] de cada item faltando
           + custo dos pré-requisitos consumidos que também faltam (sem contar em dobro)
  RANDOM   = valor esperado (ex.: pet do BA = 1000 High Gambles × 500 pts), mostrado à parte
  MILESTONE= mostra "faltam N vitórias/kills", sem converter em moeda
  restante[moeda] = max(0, custo[moeda] + metas_extras[moeda] − saldo[moeda])
  horas = max(restante[moeda] / taxa[moeda])     # gargalo entre as moedas
```

### Decisão sobre os dados (27/09/2026)
- **Saldos, itens obtidos e metas:** sempre do jogo, em tempo real.
- **Preços e itens das lojas:** embutidos no plugin (gerados da wiki por `scripts/generate-data.ps1`).
- **Atualização:** GitHub Action semanal (`.github/workflows/update-data.yml`, segundas 09:00 UTC, em
  Windows/PowerShell 5.1) regenera os dados, roda os testes e abre um pull request quando algo mudou.
  Depois do merge, publicar uma versão nova no Plugin Hub.
- Descartados por ora: download opcional de dados do GitHub, leitura de preços nas lojas e consulta
  direta à wiki em tempo de execução.

### Como os preços se mantêm atualizados (opções avaliadas)
1. **Leitura no jogo (instantâneo):** ao abrir uma loja, o plugin lê os preços da interface e substitui
   os dados embutidos, só para aquele jogador.
2. **Dados no GitHub (horas, opcional):** ao iniciar, o plugin pode baixar um `rewards.json` mais novo do
   repositório do projeto (com o aviso de acesso externo que o Plugin Hub exige).
3. **Gerador automático (dias):** uma GitHub Action roda `scripts/generate-data.ps1` toda semana e abre um
   pull request quando a wiki mudou.

### Status do passo 2 (projeto + cálculo) — concluído em 27/09/2026
- Projeto Gradle a partir do `runelite/example-plugin` (Java 11), pacote `com.rewardshopplanner`.
- `data/`: modelo dos JSON (lidos com o Gson do RuneLite, sem reflection).
- `calc/PlannerCalculator`: custo por página (itens compartilhados aparecem nas duas) e total da conta
  (cada item uma vez), sets pagos uma vez, pré-requisitos de upgrade, revenda conforme o tipo de conta,
  metas extras e saldo restante (bruto e líquido).
- 13 testes passando, entre eles a conta da Forestry (122.100 bruto / 108.100 líquido) e os totais da
  wiki (Trouble Brewing, Vale Totems, MTA).
- **Decisão do usuário:** quando um item é vendido em mais de uma loja (hoje só o Prospector kit:
  Motherlode Mine ou Volcanic Mine), o **jogador sempre escolhe** a loja. Sem escolha, o item fica como
  "escolha pendente" e não entra em nenhuma conta; não existe padrão automático.
- Autor no Plugin Hub: **Matelaa**.

### Status do passo 3 (v0.1 jogável) — implementado em 27/09/2026, aguardando teste no jogo
- Sincronização do collection log: ao abrir uma página (script `COLLECTION_DRAW_LIST`), lê os itens
  por ID (fallback: posição, nome) e a opacidade (0 = obtido). Também escuta "New item added to your
  collection log" quando o nome não é ambíguo.
- Moedas: itens contados no banco (salvo na última visita) + inventário; 7 moedas lidas de
  varp/varbit; as demais digitadas no card da página.
- Tipo de conta: varbit `IRONMAN` (config permite forçar).
- Estado salvo por personagem no perfil do RuneLite (`rewardshopplanner.state`).
- **Reformulação do painel (decidida com o usuário):**
  - Tela inicial: "My goals" (soma de tudo que está na meta + metas extras, já descontando o saldo),
    metas extras e a lista de páginas agrupada por aba (Minigames, Other, Bosses).
  - Clicar numa página abre os itens dela com "← All pages".
  - Cada item tem **dois controles**: ✓ = tenho (vem do log; clicar corrige manualmente) e a caixa
    = quero (entra na meta). **A meta começa vazia**; botões "Want all" e "Clear" por página.
  - A página mostra o **custo** da meta dela com o saldo embaixo (o saldo é compartilhado, então a
    página nunca diz "done"); o "quanto falta" fica em "My goals".
  - Escolha de loja só aparece quando o item está na meta; campo de pontos manuais só para moedas
    usadas pela meta da página.
- Correções manuais de "tenho" são descartadas quando o log concordar.
- 25 testes (inclui casamento do log e correções manuais).

### Roadmap sugerido
1. **v0.1**: dados + cálculo + painel com moedas de **item** (Forestry, Castle Wars, GOTR, Sepulchre,
